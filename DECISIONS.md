# Decisions

Status of every decision: **proposed, waiting for Thức**. The code uses the default in the second column. To change a decision, change this file and the code in the same PR.

## How to settle a decision

1. Read the options of the decision in `docs/plan.md` (D1–D11) or in the tables below (C1–C21).
2. Keep the default, or pick another option.
3. Tell Claude in one line, for example: "D4: keep the default. C5: 20%, but at least 2 KB."
4. Claude writes "decided by Thức, <date>" next to the decision, and changes the code or the config in the same PR.

Settle each decision before the phase that uses it. Earlier is not better: a threshold that you set before you have data is a guess.

| Decision | Settle before | Cost of a change later | Where the value lives |
| --- | --- | --- | --- |
| D1, D2, D7 | now (confirm) | High: the code is built on them | code |
| D4. Models | the first `harness measure` | Medium: a new model starts a new epoch, and a new judge model needs a new calibration | `harness/pinned-config.yaml` `models:` |
| D8. Eval set, task source | the first eval task | Medium: the task source decides where the eval store lives | eval store |
| D6. Session launch | after `harness doctor --live` | High if a live probe fails: `roles.ts` changes | code |
| D10. Lesson store; C5. Growth limit | Phase 2 (the first improvement loop) | Low | user config; `growth_limit_pct` in `harness/pinned-config.yaml` |
| D9. Where eval runs | Phase 3 (the first holdout round) | Low now; the container is not built | `HARNESS_EVAL_IMAGE` |
| D5. Library scope | Phase 4 (the second project) | Low | template library repo |
| D3. Recursion budget | Phase 5 | Low: one config value | `loop.k_par` |
| D11. Fold R roles into fewer sessions | after the first E1 round on dev (Phase 3) | Low now; nothing is built | a new eval arm in `orchestrator/src/loop/round.ts` |
| C17. Phase 6 data gate; C18. Efficiency route | Phase 6, after you see data in `harness lessons stats` | Low | C17: `PHASE6_GATE` in `orchestrator/src/extras/lessonstore.ts`; C18: `weights.yaml` of the eval store |

| Decision | Default in the code | Where the code applies it |
| --- | --- | --- |

| D11. Fold R roles | A: the roles of Harness² (two editors, two probes, a composer). Proposal: B, an eval arm with one editor, after the first E1 round | `orchestrator/src/loop/pipeline.ts` |

Phase 6 (docs/plan.md) uses the lesson store to make the harness smarter (a higher score) and more efficient (the same score with fewer tokens). Phase 6 does not train a model: it changes only the text and the numbers of the template. Thức confirmed this on 2026-10-23.
